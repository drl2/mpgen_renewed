WHAT IS THIS?
=============
This directory contains a complete analysis of the MPGEN application and a 
detailed plan to rewrite it as a streamlined standalone HTML/JavaScript SPA.

The old architecture separates:
  • BACKEND: Python/Django REST API serving data from SQLite
  • FRONTEND: React.js web UI consuming the API

The new architecture will be:
  • SINGLE SPA: Vanilla HTML/CSS/JavaScript with embedded JSON data
  • GOAL: Simplify maintenance, reduce dependencies, improve performance

KEY FINDINGS (TL;DR)
====================

ARCHITECTURE:
  • Current: Django + React + SQLite
  • Target: Vanilla JS + JSON data
  • Complexity: MEDIUM (straightforward logic)

CODEBASE SIZE:
  • Backend: 1,362 lines Python
  • Frontend: 3,900 lines JavaScript/React
  • Database: 31 tables, ~385 config rows
  • API: 17 GET endpoints + 1 POST endpoint

CRITICAL COMPONENTS:
  • Character.Generate() algorithm (378 LOC) - complex conditionals
  • Excel export (163 LOC) - needs migration to SheetJS or CSV
  • Selection dropdown logic - 17 identical components
  • Material-UI styling - tight coupling to remove

ESTIMATED EFFORT:
  • Phase 2 (Framework): 2-3 weeks
  • Phase 3 (Logic): 3-4 weeks
  • Phase 4 (UI): 4-6 weeks
  • Phase 5 (Testing): 2-3 weeks
  • Phase 6 (Deploy): 1-2 weeks
  • TOTAL: 13-21 weeks


WHAT'S NEW IN THE SPA?
======================

✓ SMALLER: 1,362 + 3,900 = 5,262 LOC → estimated ~1,500-2,000 LOC (70% reduction)
✓ FASTER: All data embedded (no API calls after load)
✓ SIMPLER: No Django, React, Material-UI overhead
✓ BETTER: Vanilla JavaScript easier to maintain
✓ SAME: 100% feature parity with legacy app
