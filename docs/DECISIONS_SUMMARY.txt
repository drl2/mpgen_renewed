DECISION 3: Character History Storage
─────────────────────────────────────────────────────────────────────────────
  Question:  Should saved characters be stored locally or in backend?
  Answer:    ✅ LOCALLY (browser localStorage)
  Impact:    • No backend database for user saves needed
             • Each character: ~5-10 KB JSON
             • Capacity: ~50-100 characters per browser
             • ~2-3 days implementation effort
             • New features:
               - Save character with name
               - Load previously saved character
               - List all saved characters
               - Delete character
               - Export to JSON file
             • Cleaner architecture (no backend coupling)
  Reference: PHASE1_ANALYSIS.md section 20 / STAKEHOLDER_DECISIONS.md section 3


DECISION 4: Excel Export Format
─────────────────────────────────────────────────────────────────────────────
  Question:  Is current Excel export format critical, or can it be simplified?
  Answer:    ✅ CURRENT EXCEL FORMAT REQUIRED
  Impact:    • Use SheetJS library (JavaScript Excel export)
             • Pre-formatted Excel workbook needed
             • Two sheets: "Official Sheet" + "MPGen Character"
             • Cell-by-cell population from charsheetmaker.py logic
             • ~3-4 days implementation effort
             • ~50 KB library addition
             • Binary .xlsx format (not CSV)
  Reference: PHASE1_ANALYSIS.md section 20 / STAKEHOLDER_DECISIONS.md section 4
